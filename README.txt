PRINT PREP 1.1 — подготовка фотографий к печати
============================================

Что делает программа
--------------------
Выбираете папку → задаёте размер и цвет → при необходимости поправляете
отдельные кадры → нажимаете «Подготовить к печати».
В той же папке появляется новая PrintPrep_дата_время с готовыми копиями.
Исходники не перезаписываются. Каждый запуск создаёт отдельную папку.
Обработка локальная: приложение не отправляет фотографии в интернет.
Прямая печать и управление драйвером принтера не предусмотрены.

Как получить Windows-приложение
------------------------------
Сборка требует Windows 10/11 x64 и Python 3.12 x64 с Python Launcher
(официальный python.org). Распакуйте проект в обычную доступную папку.
Если py сообщает «No runtime installed that matches 3.12», установлен
только launcher/менеджер Python. Откройте PowerShell и выполните:
  py install 3.12
Если команда install не поддерживается, установите Python 3.12 x64 с
https://www.python.org/downloads/windows/ и Python Launcher.
Проверьте: py -3.12 -c "import sys; print(sys.version)"
Затем дважды щёлкните build_exe.bat. При первой сборке нужен интернет для pip.
Сценарий установит зависимости, выполнит тесты, соберёт PrintPrep.exe,
проверит встроенный self-test и создаст dist\PrintPrep-Windows-x64.zip.
Коллегам передавайте ZIP целиком: exe, инструкция, контрольная сумма,
уведомления о сторонних компонентах и licenses. Python им не нужен.
Права администратора для работы программы не требуются.
Не храните exe в папке с оригиналами, если нет необходимости.

Альтернатива: после загрузки проекта в GitHub запустите workflow
«Windows build» во вкладке Actions и скачайте артефакт после успеха.
CI не запускается, пока код не отправлен на GitHub.
Сборка PyInstaller должна выполняться на Windows: Linux не создаёт
проверенный Windows exe. Наличие сценария не означает наличие готового exe.
Подпись Authenticode не включена: она требует сертификата издателя.
Перед передачей коллегам проверьте exe на чистой Windows и сделайте
пробный отпечаток. Облачная проверка Linux не подтверждает Windows-печать.

Запуск из исходников
-------------------
Windows:
  py -3.12 -m venv .venv
  .venv\Scripts\python -m pip install -r requirements.txt
  .venv\Scripts\python print_prep.py
Linux/macOS с рабочим Qt desktop:
  python3 -m venv .venv
  .venv/bin/python -m pip install -r requirements.txt
  .venv/bin/python print_prep.py

Обработка папки — основной сценарий
----------------------------------
1. Выберите папку. Просмотр файлов пока не запускается.
2. Выберите пресет: карточкой или в едином поле «Выбранный пресет».
   Там есть встроенные и все ваши сохранённые пресеты.
3. Можно сразу нажать «Подготовить N фото» либо сначала просмотреть партию.
   Готовые файлы появятся в новой PrintPrep_*; оригиналы не меняются.

Свой пресет: выбрать, изменить, сохранить
---------------------------------------
«Сохранить как новый» сохраняет текущие параметры под именем и сразу
ВЫБИРАЕТ новый пресет. В поле отображается «Мой · название».
«Изменить» открывает именно выбранные параметры. Настройки разделены
на вкладки «Размер», «Цвет и файл», «Коррекция», «Нейро ×2».
Справа — живой предпросмотр выбранного / первого снимка партии.
Изменённый пресет помечается «изменён», включается кнопка сохранения.
Для своего пресета «Сохранить изменения» обновляет его под тем же именем.
Встроенный можно изменить для текущей партии и сохранить как свою копию.
«Отмена · вернуться» откатывает несохранённые изменения в окне настроек.
Меню «Ещё» позволяет переименовать, удалить и перенести рецепт JSON.
Загрузка другого пресета сохраняет индивидуальные правки фотографий.

Размер в пикселях и сохранение деталей
-------------------------------------
По умолчанию в новой установке выбран «Без уменьшения»: сохраняются
исходные пиксели, JPEG 95, sRGB. Предыдущий сеанс может восстановить
выбранный ранее размер — итоговые параметры всегда видны перед экспортом.

• «Без уменьшения»: без ресайза; при ручной обрезке остаются пиксели кадра.
• «Печатный размер»: мм и PPI определяют число пикселей. Например,
  10×15 см / 300 PPI — всего 1181×1772 px. Это уменьшение большого исходника,
  а не универсальное улучшение качества. Число уменьшаемых файлов видно.
• «Точный размер»: ширина и высота в пикселях. Для ровно 3840×2160 отключите
  «По ориентации снимка». Вписывание даёт поля, заполнение обрезает края.
• «Длинная сторона»: например, 3840 px (4K), вторая сохраняет пропорции.
  Кадр 3:2 получится 3840×2560, а не 3840×2160.

В пиксельных режимах PPI — метаданные; изменение PPI не добавляет пиксели.
Поля в миллиметрах доступны только в режиме печатного размера.
Для копии без потерь выбирайте исходные пиксели и TIFF LZW. JPEG всегда
повторно сжимается. Исходный ICC приводится в рабочий sRGB, поэтому это
не широкогамутный 16-битный архив, даже в режиме исходных пикселей.

Посмотреть и подогнать: живой редактор
------------------------------------
В просмотре партии выберите снимок, затем «Кадр и коррекция».
Ползунки экспозиции, контраста и насыщенности меняют картинку ДО сохранения.
Расчёт идёт в фоне; быстрые изменения объединяются, статус показывает расчёт.
«Результат» показывает итог; «Кадрирование» — рамку для перетаскивания.
При изменении рамки включается обрезка ДЛЯ ЭТОГО СНИМКА, даже если общий
пресет вписывает фото. Поворот сам по себе не заставляет обрезать кадр.

«Без улучшений» сравнивает тот же размер и кадр без цветокоррекции/нейро.
«Вписать / 100% / 200%» меняет масштаб просмотра, не экспортируемый размер.
100% отображает пиксели результата, а не уменьшенную подменную картинку.
Нейро ×2 рассчитывается тем же движком, что экспорт; выключение флажка
сразу убирает эффект для этого снимка. «Отменить правку» / Ctrl+Z возвращает
предыдущее изменение, «Сбросить» — индивидуальные параметры по умолчанию.
«Применить к снимку» сохраняет правки, «Отмена» оставляет исходные параметры.
Рабочий цвет редактора — sRGB. Для профиля машины есть ICC-проба в просмотре
партии и окне настроек; это приближённая симуляция на sRGB-дисплее.

Пункты «Папка», «Пресет», «Результат» слева позволяют вернуться без потери
текущей партии и правок. Горизонтальных списков в формах нет; полосы у
изображения появляются только при увеличении, если оно не помещается.

JPEG, TIFF, PNG, WebP и BMP включаются в список. PrintPrep_* исключаются.
RAW/HEIC/GIF не поддерживаются. Ошибки сканирования показываются отдельно.
Повторный экспорт создаёт новую папку. Остановка завершает текущий файл;
готовые копии сохраняются. Ошибка одного фото не останавливает остальные.

Результат
---------
Файл photo.jpg превращается в photo.jpg.jpg или photo.jpg.tif:
исходное расширение в имени предотвращает совпадения photo.jpg/photo.png.
Для подпапок сохраняется структура каталогов.
JPEG: 8 бит/канал, базовый последовательный, качество до 95, 4:4:4.
TIFF: 8 бит/канал, LZW без потерь. Выход RGB либо CMYK по ICC.
В каждом файле есть ICC и метаданные плотности PPI.
Исходные EXIF/GPS/миниатюры не копируются. Поворот физически применён.
Прозрачность исходника сводится на белый фон; цвет полей задаётся отдельно.
report.csv (UTF-8 BOM, разделитель ;) открывается в Excel.
report.json содержит параметры, правки, результат по каждому файлу.
Статусы: ok — готов; error — ошибка; skipped — запрещённое увеличение.
Отчёты содержат локальные пути: учитывайте это при передаче папки.

Разрешение: PPI, DPI и детали
----------------------------
Пиксели = миллиметры / 25,4 × PPI, округление до ближайшего целого.
100 × 150 мм при 300 PPI → 1181 × 1772 пикселя.
4 × 6 дюймов при 300 PPI → 1200 × 1800 пикселей.
Параметр 1440/2880 DPI в драйвере — это точки чернил, не PPI фотографии.
Изменение метки DPI не добавляет деталей. Программа реально меняет
число пикселей, оценивает исходное разрешение после кадрирования и
предупреждает об увеличении, <240 PPI и особенно <150 PPI.
Эти пороги — подсказки, а не гарантия брака: важны дистанция просмотра,
материал и требования лаборатории. Для крупного плаката 150 PPI может
быть достаточно; для небольшого отпечатка обычно выбирают 300 PPI.
Выключите «Разрешить увеличение», чтобы маленькие снимки пропускались.
Увеличение выполняется Lanczos и не восстанавливает потерянные детали.

Цвет: безопасный выбор
---------------------
Фотолаборатория / онлайн-заказ / сублимационный фотопринтер:
обычно sRGB и JPEG; подтвердите у оператора. У многих машин собственный
внутренний цветовой процесс, поэтому автоматический CMYK здесь вреден.

Свой струйный Epson/Canon/другой:
ICC должен соответствовать модели + бумаге + чернилам + режиму драйвера.
Если уже конвертируете в выходной ICC в Print Prep, далее нужна цепочка,
которая не применит профиль второй раз. Не используйте обычный просмотрщик
для печати заранее преобразованного файла без понимания его управления
цветом. Обычно для домашней печати удобнее оставить экспорт sRGB и
поручить ОДНО преобразование цветоуправляемой программе печати.

Типография / цифровая машина / RIP:
узнайте точный профиль и требования. Только тогда выбирайте «ICC» и
нужный профиль CMYK/RGB. Профиль SWOP/FOGRA по умолчанию не назначается.
Никакой профиль не угадывается из модели принтера.
Программа не делает PDF/X, метки реза, вылеты, спуск полос, лимит краски
сверх того, что задаёт ICC, или проверку требований конкретного RIP.

Исходный встроенный ICC сначала преобразуется в рабочий sRGB (LittleCMS).
RGB без ICC считается sRGB с предупреждением. Для непрофилированных
Adobe RGB/Display P3 это может быть неверно: сначала назначьте правильный
исходный профиль во внешнем редакторе. CMYK/Lab без ICC отклоняются.
Далее коррекции/геометрия в 8-битном sRGB и преобразование в выбранный
выходной ICC. Исходные широкие охваты сужаются до sRGB; это не замена
16-битному широкогамутному процессу Photoshop/Affinity.

«ICC-проба» приблизительно симулирует профиль в sRGB. Она предполагает
sRGB-монитор, не использует системный профиль монитора и не симулирует
белизну бумаги. Проба не гарантирует совпадения с печатью. Для оценки
нужны калиброванный монитор, нейтральное освещение и пробный отпечаток.
ICC, который лаборатория даёт только для soft proof, НЕ выбирайте для
конвертации экспортируемого файла без её явного указания.

Ограничения и рабочие привычки
-----------------------------
• 16/32-битные и многостраничные/анимированные файлы отклоняются.
  Экспортируйте 8-битную RGB-копию в редакторе; оригинал сохраните.
• Лимит 80 Мп на исходник/результат. При больших файлах нужно много RAM;
  обработка идёт последовательно, интерфейс не выполняет экспорт сам.
• Наклонный горизонт, перспектива, шумоподавление, удаление дефектов,
  распознавание лиц, HEIC/RAW и загрузка в фотосервисы не реализованы.
• Без полей в драйвере часто означает дополнительное расширение/обрезку.
  Оставляйте важные объекты в безопасной зоне; уточняйте её у оператора.
• Если фото уже обработаны, отключите автоулучшения в лаборатории.
• Настройки сохраняются локально в пользовательских настройках Qt.
  Цветовой профиль остаётся внешним файлом, встроен он только в результат.

Алгоритмическая коррекция и библиотека пресетов
----------------------------------------------
В разделе «Алгоритмическая коррекция» есть готовые варианты:
«Естественная печать», «Портрет · мягкий», «Пейзаж · детали»,
«Слабый свет · бережно», «Предметная · чисто». По умолчанию — без коррекции.
Сила задаётся в процентах. Тени, сжатие светов, микроконтраст,
вибрация цвета, теплота, оттенок и цветовой шум регулируются отдельно.
Это алгоритмы без нейросетей, без моделей и сетевых запросов.

Движок использует временный float32 линейный RGB, карту светлоты с
сохранением границ и обработку цвета плитками. Для скорости коррекции
выполняются на сетке итогового отпечатка после качественного ресайза.
Конечный рабочий процесс остаётся 8-битным sRGB, а не RAW/16 бит.
Автотон ограничен ±0,35 EV в средних тонах с закреплением чёрного/белого.
Цветовой шум — медиана в Cb/Cr, не удаление яркостного зерна и не NLM.
Микроконтраст может усилить шум; подавление цвета — съесть цветовые детали.

«Осторожный авто-ББ» включается отдельно. Если нейтральных участков мало,
он отказывается от коррекции; даже при уверенной оценке может убрать
намеренный тёплый свет. Всегда сравнивайте с исходником.
«Теплее / холоднее» — безразмерная коррекция, не физическая температура K.
Вибрация цвета умеренно действует на оранжевые оттенки, но не распознаёт
кожу/лица и не гарантирует сохранение любого оттенка.
Предпросмотр показывает фактический размер результата и причины пропуска
нейроувеличения. Пробный отпечаток остаётся обязательным для оценки печати.

«＋ Мой пресет» сохраняет размер, профиль, формат и обработку под именем
машины/бумаги в локальную библиотеку. В выпадающем списке «Мои пресеты»
их можно загрузить; рядом — удаление. Загрузка сохраняет ручные кадры.
Для переноса коллегам используйте «Сохранить рецепт» (JSON), который
также содержит индивидуальные правки. ICC-файл переносится отдельно.

Нельзя обещать «лучше Photoshop» без одинаковых задач и слепой оценки
реальных отпечатков. Локальное измерение и источники — в RESEARCH.md.

Нейроувеличение: компактный необязательный режим
------------------------------------------------
Откройте вкладку «Нейро ×2» в настройках пресета или флажок в редакторе.
По умолчанию выбран обычный Lanczos. Предобученная модель ~39 КБ уже
включена в приложение; загрузки из интернета и GPU не нужны. Движок
OpenCV добавляет размер к дистрибутиву, хотя сама модель очень мала.
Это известная компактная модель, а не новейшая фотореалистичная реставрация.

Сеть применяется только при реальном увеличении более 5%, один раз ×2.
Сила смешивает нейрорезультат с Lanczos. Для малого промежуточного кадра
доступен лимит 8 Мп: при большем кадре применяется Lanczos с предупреждением
в отчёте. Если нужно больше ×2, остаток увеличивается обычным способом.
Исходная оценка PPI не повышается от дорисованных пикселей.
Предпросмотр запускает сеть по тем же правилам, что экспорт. Сравнивайте
при 100% и на отпечатке. Если увеличения нет, сеть не применяется — это
явно указано в статусе. FSRCNN увеличивает, а не реставрирует любое фото.
Особенно проверяйте лица, мелкие надписи, волосы и регулярную фактуру.

Модель лицензирована Apache-2.0; источник, атрибуция и SHA-256 находятся
в assets/models/README.md и licenses/FSRCNN-Apache-2.0.txt. Ни TensorFlow,
ни PyTorch для работы не нужны. Изученный Real-ESRGAN не входит в сборку:
его выход может быть заметно другим, и он требует отдельной проверки.

Интерфейс 1.1
-------------
Основной экран посвящён партии. Свои и встроенные пресеты выбираются в
одном поле; выбранный и изменённый пресет видны явно. Подробные настройки
открываются отдельным большим окном с вкладками и предпросмотром справа.
В редакторе доступны живые коррекции, сравнение и отмена. Прокрутка колёсиком
над полями не меняет случайно выбранный пресет или числовое значение.
